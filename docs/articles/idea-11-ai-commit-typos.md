# Idea 11 — "AI wrote my commit messages. I typo-reviewed my own fixes."

**Angle:** story-driven (light contrarian via voice-profile hot take: using AI to write/analyze code wisely)
**Evidence:** thin — commit log typos: `d6fd920 test(keitaro): etsted leitaro untagged fixes`, `0df05c2 fix(commissions): fied commissions calcs`. Flagged as weak evidence per skill rules — real but small; framed honestly as a self-deprecating aside, not a big claim.

## LinkedIn (compact essay)

My last few commit messages have typos in them. "etsted" instead of "tested." "fied" instead of "fixed." AI-assisted, unreviewed, shipped straight into permanent history.

Here's the thing — the tool didn't cause this. I generate commit messages fast now, and fast means I stopped giving them the 5-second read I used to give my own typing. The bug isn't "AI wrote it wrong." The bug is "I skipped the one step that catches wrong."

I still think using AI to write and analyze code is one of the better moves available right now. Not because it's magic — because it's fast at the parts that were never the interesting part of the job. But fast output plus zero review is exactly where it costs you, and a typoed commit message is the harmless version. The same skipped-review habit applied to a generated migration or a generated auth check is not harmless.

Takeaway: treat AI output like a junior engineer's PR — quick to produce, still worth the read. The speed is real. So is the discipline it removes if you let it.

Where has skipping the review — AI-generated or not — actually bitten you?
